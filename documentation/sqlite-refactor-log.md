| 2026-05-21 | Add `academic_years` as a first-class table; classes become year-specific via `academic_year_id`. | User confirmed multi-year operation; without academic years, year-over-year reporting collides on class name. | Masi pivots to single-year operation. |

| 2026-05-21 | Add `child_class_memberships` with academic year; `children.class_id` becomes a current/compatibility pointer. | Children can change classes mid-year, and old work must stay linked to the old class for reports. | Masi decides children never change classes mid-year. |

| 2026-05-21 | Add `class_ea_assignments` and `group_ea_assignments`; EAs can be assigned at child, class, or group level. | User confirmed Masi uses a mix of all three assignment levels in practice. | Masi simplifies to a single assignment level. |
| 2026-05-21 | Add `grouping_versions` and `class_grouping_state` for versioned grouping. | EAs regroup mid-year and prior groupings must remain as history. | Masi decides regrouping is rare enough to do in place without versioning. |
| 2026-05-21 | Skip Zazi tables `education_assistants`, `child_school_enrollments`, `staff_identity_links`, external ID bridges, `teacher_school_assignments`, and `class_teacher_assignments`. | Each can be added later if the operational model needs it; carrying them now adds RLS surface without clear value. | Admin/PM features need a separate EA roster, child mobility between schools becomes common, or teacher history becomes reportable. |
| 2026-05-21 | Write policy for child-specific event rows uses an OR across direct child assignment, class assignment plus active class membership, and group assignment plus active group membership. | EAs can earn write access through any of the three assignment paths; all paths must include both active assignment and active membership filters to prevent stale-assignment writes. | A new assignment path is added, or the multi-path OR becomes too expensive per row. |
| 2026-05-21 | Disable direct mobile hard delete on `children`; use `delete_child_if_no_history(child_id)` for the rare no-history delete path. | Child event rows have cascading FKs, so direct delete could silently erase assessment, mastery, and attendance history. Children with history should be archived or unassigned instead. | Product introduces a server-side admin console with explicit audited delete approval. |
| 2026-05-21 | Archive repositories must end active assignments/enrollments in the same transaction as the archive marker. | Archived children/classes/groups should not stay active in My Children, class, group, or assignment reports. | Archive semantics change to mean display-only hidden state. |
| 2026-05-21 | Admin-precreated classes are supported; EAs may self-assign only when the class is visible through their active school/programme assignment. | Masi will have admin-created/prepopulated classes; requiring `classes.created_by = auth.uid()` would block legitimate mobile claiming. | Admin workflows move all class assignment through service-role only. |
| 2026-05-21 | Future active-year rollover is a deliberate migration transaction, not automatic year switching. | The active-year unique index hard-fails multiple active years; future maintainers need to deactivate the old year and activate the new year atomically. | Masi wants an admin UI to change active years interactively. |
| 2026-05-21 | Make the SQLite staging launcher responsible for local Android SDK discovery and a fixed Metro port. | Codex can use the user's Android emulator when the project launcher injects `ANDROID_HOME`, `ANDROID_SDK_ROOT`, and SDK tool paths; pinning the staging Metro port avoids non-interactive Expo prompts when another Metro server already owns 8081. | The repo moves to a managed dev-client workflow with a different launch path. |
| 2026-05-21 | Use normalized SQLite repositories as the Plan 3 domain boundary and keep `src/utils/storage.js` as a temporary facade. | Repositories now own SQL, transaction boundaries, outbox enqueue, and normalized table contracts while current contexts/screens continue using named storage methods. | Plan 5 finishes migrating contexts/screens directly to repositories and the facade can be removed. |
| 2026-05-21 | Preserve current screen-shaped payloads temporarily in `local_state` sidecars while SQLite stores normalized rows. | Existing screens still expect AsyncStorage-style objects such as session `children_ids` and assessment letter arrays; the sidecar prevents a UI rewrite inside Plan 3 while normalized rows become the source for sync. | Plan 5 removes remaining screen-level storage callers and reads normalized repository view models directly. |
| 2026-05-21 | Treat child creation as four domain writes when class is known: child, EA assignment, programme enrollment, and class membership. | The schema has four durable rows for that action, so Plan 3 enqueues four matching outbox items rather than inventing a fifth side-effect row. | A later sync contract adds an explicit audit/event row for child creation. |
| 2026-05-21 | Relationship rows created by child save use fresh UUIDs plus active-row lookups for idempotency. | Deterministic child/user/programme/class IDs erase handover history when an ended relationship later becomes active again; active unique indexes already enforce single active rows. | A future sync model requires deterministic client-generated IDs for conflict-free relationship creation. |
| 2026-05-21 | `deleteClass` and `deleteGroup` are archive aliases in the storage facade layer. | Mobile hard delete without a synced outbox signal creates server orphans; archive preserves history and keeps a syncable mutation. | Product explicitly adds no-history hard-delete flows for classes or groups. |
| 2026-05-21 | Local-only legacy session metadata stays in SQLite but is stripped from session outbox payloads. | Current screens need legacy fields until Plan 5, but Supabase should not receive `__legacySession` implementation details as opaque session activity data. | Plan 5 removes legacy session fields from the repository shape entirely. |
