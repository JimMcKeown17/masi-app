## Design decisions (locked; the REVISED spec sections C/D/E govern)

1. **Per-scope result shape:** `pullPreloadedChildData` → `{ activeProgrammeId, scopes }`; scopes: `programmeAssignment`, `children`, `childEaAssignments`, `childProgrammeEnrollments`, `childClassMemberships`, `classes`, `groups`, `groupEaAssignments`, `childrenGroups`; each `{ ok, rows, complete, failureKind: null | 'query' | 'transport' | 'dependency', error? }`. Rejected requests AND Supabase-returned network-shaped failures classify `transport`; RLS/query errors classify `query`; scopes skipped because a parent failed classify `dependency`. Legacy top-level arrays and the shared `errors` array are removed IN THE SAME TASK as all seven consumer/fixture migrations (no broken intermediate commit).
2. **New pull queries (relationship-specific scopes):** (a) direct active `child_ea_assignments` for me with `children(*)` embedded (FK-safe persistence of assigned-but-unenrolled children); (b) direct active `child_programme_enrollments` for `activeProgrammeId` with `child_id IN` my acknowledged assigned children -- issued in BOUNDED CHUNKS of at most 200 ids per request (PostgREST serializes the whole IN list into the URL), aggregated and deduplicated; if ANY chunk fails the whole cpe scope is `failureKind: 'query'`; `complete` is computed over the aggregate; (c) the groups query keeps its gea `!inner` but selects FULL `group_ea_assignments(*)` rows, which are now persisted. Dependency graph: cea depends only on programmeAssignment; cpe depends on programmeAssignment + cea; children/ccm/classes hang off the intersection query; gea rides groups. The children intersection query acknowledges NOTHING about assignments or enrollments.
3. **Truncation guard:** `PULL_SCOPE_COMPLETENESS_LIMIT = 1000`; a scope at the limit is `complete: false` (persisted, not reconciled, logged).
4. **Reconcile mechanics:** batch APIs accept `(rows, { reconcile })`; the reconcile runs at the END of the happy-path transaction only. `runBatchWithPerRowFallback` returns `{ applied, skipped, failed, ended, fallbackUsed, reconcileCompleted }` and LOGS the original batch error on fallback. Acknowledged id sets are passed as ONE JSON string parameter and consumed via `id NOT IN (select value from json_each(?))` (portable under a 999-bind limit). Reconcile updates stamp the end column with the pull timestamp, bump `updated_at`, keep `sync_status = 'synced'`, enqueue NOTHING; candidates are always `sync_status = 'synced'` only.
5. **Reconcile semantics** = the spec's REVISED table verbatim: cea by its own direct scope; cpe by its own direct scope (`programme_id = :pid AND child_id IN acknowledgedAssignedChildIds`); ccm per returned children; gea by acknowledged groups (`unassigned_at`, mine, programme-scoped); cgm per acknowledged groups; class cea per acknowledged classes. NEVER `groups.archived_at`, `classes.archived_at`, or `children.archived_at` from absence -- entity tombstones arrive on the rows themselves.
6. **Group read model:** `getGroups({ userId, programmeId })` joins an active `group_ea_assignments` row for that EA (assignment-scoped, matching the server); locally-created groups already produce a local gea row (existing producer). The `childrenGroups` PUBLICATION is scoped to visible groups (repository read joining non-archived, assigned groups); memberships of unacknowledged/absent groups are never destructively ended. One-time catch-up: pre-4B pulled groups have no local gea rows until the first 4B pull persists them (dev backend only; note in log).
7. **Gating:** a scope reconciles only when `ok && complete`, its predicate's dependency scopes are `ok`, and `activeProgrammeId` is present. **Mass-end circuit breaker with recovery (re-review fix f):** inside the transaction, if the would-end count exceeds 10 AND exceeds 50% of the scope's local active synced candidates, skip the reconcile UPDATE, set `reconcileCompleted: false`, emit a loud support log, AND persist a durable breaker note in `sync_state` (scope name, counts, timestamp). SyncStatusScreen surfaces the note as a needs-attention card ("Large roster change from Head Office is waiting" + Apply action); applying sets a one-shot authorization flag that the next `pullFromServer` passes through to that scope's reconcile (`bypassBreaker: true`), then clears the note on success. A breaker note also clears automatically when a later pull's would-end count falls back under the threshold. The ClassesContext pull is modeled as two stages so no-programme yields `classes`/`classEaAssignments` `{ ok: false, failureKind: 'dependency' }` while an active programme with zero classes yields `{ ok: true, rows: [], complete: true }` (which DOES reconcile).
8. **State publication:** `mergeServerRows` deleted (file, test, context plumbing, `shouldApplyPulledRows`). `pullFromServer` keeps the R14 cache-first publish, then after persistence+reconcile publishes once more from fresh SQLite reads. The pre-persist owner-scoped `pendingDeleteIds` filter stays.
9. **Scheduling:** `DOMAIN_PULL_STALENESS_MS = 15 * 60 * 1000`. Stamp `setPullState('child_data_pull' | 'classes_pull', { lastPulledAt })` only when no scope has `failureKind: 'transport'` AND every reconcile-requesting scope reports `reconcileCompleted: true`. `OfflineContext` bumps `domainPullNonce` on reconnect/foreground when either stamp is missing or stale. Contexts subscribe with a previous-nonce ref initialized from the initial value (mount must not double-pull). Single-flight is USER-KEYED (`{ userId, promise }`): join only on matching user; a user transition starts its own pull; `finally` clears the ref only if it still holds that exact promise.
10. **No sync-engine, RLS, payload, outbox, or Supabase-migration changes; no new SQLite migration.** Follow-ups recorded at wrap (GitHub issues): server-authoritative acknowledgment RPC (the complete answer to RLS under-return); reference-table hard-delete strategy; product decision on offline retention of server-deleted sessions/assessments.
