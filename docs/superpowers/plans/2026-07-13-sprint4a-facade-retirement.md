## Design decisions (locked; do not relitigate — spec sections A and B govern)

1. Full facade retirement this branch; NO interim same-transaction sidecar patch.
2. `src/services/deviceSettings.js` owns `user_profile` + `assessment_capture_mode` over `localStateRepository`; storage keys unchanged (no data migration); capture-mode validation (`isValidCaptureMode` + `resolveCaptureMode`) moves with it verbatim.
3. Schools: `fetchAndCacheSchools` persists via `schoolsRepository.replaceFromServer` and returns the rows; `ClassesContext` reads `schoolsRepository.getAll()`; the `storage_payload:schools:list` copy is dead.
4. The facade's `getClasses` display fallback (`staff_id` defaulting to `created_by`, `storage.js:385`) is DELETED, not relocated: verified 2026-07-13 that no screen, component, or util reads `staff_id` off class rows (the facade line is the only producer; classes has no local `staff_id` column). Same for `programme_id` on class rows (context `addClass` stamps it for the outbox payload only). No facade read-shaping survives: contexts consume `mapDomainRow` shapes (nulls present, `sync_status` present). Shape-pin tests (Task 1) define the consumer-visible contract that must hold before and after.
5. Batch APIs are per-table, named `saveServer<Thing>Rows(rows)`, one writer transaction each, reusing the existing per-row save (with its pull-clobber guard and RLS producer guards) via `{ transaction }`; return `{ applied, skipped }` counts. Existing single-row signatures unchanged.
6. (AMENDED BY R1 — the disposition wins.) `pullFromServer()` = network pull → batched persist in the R4 dependency order → FRESH post-commit SQLite snapshot → `mergeServerRows` against that snapshot → set state once. `refreshFromCache()` is SQLite-reads-only → set state. Sync-completion effects call `refreshFromCache()` ONLY (this is audit #1 link d). Mount/sign-in runs `pullFromServer()`; pull-to-refresh runs `syncNow()` then ONE `pullFromServer()`.
7. Migration v7 `local_state_sidecar_cleanup`: `delete from local_state where key like 'storage_payload:%'` plus `delete from local_state where key = 'sync_queue'` (dead legacy queue). **`sync_meta` must NOT be deleted**: the facade's sync-meta block is a dead duplicate, but the key itself is live property of `syncStateRepository` (lastSyncTime/lastSuccessfulSyncTime, `src/db/repositories/syncStateRepository.js:8`).
8. Facade-only normalization is deliberately deleted, not relocated: `'local-user'` fallbacks, `session_date`/`date_assessed` defaulting, `ensure*Exists` fabrication. Repository producer guards are the contract. Any test pinning those fallbacks updates to pin the guard rejection instead.
9. No schema change other than migration v7. No RLS, Supabase payload, `SERVER_COLUMNS`, push/archive ordering, or sync-engine change. Local-write transaction boundaries unchanged.
